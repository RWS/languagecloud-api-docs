# Termbases: structure, templates, entries, import and export

Create and update termbases and termbase templates, manage entries and cross-references, and import/export termbases.

## Create a termbase

`POST` [CreateTermbase](../reference/CreateTermbase.md) `/termbases`. Provide one of:

| Option | Body |
|---|---|
| Template | `termbaseTemplateId` |
| Custom structure | `termbaseStructure` object: `languages[]` (`languageCode`), `fields[]` |

If both are sent, `termbaseStructure` takes precedence and `termbaseTemplateId` is ignored.

```json
{
    "name": "Simple Termbase",
    "description": "A simple termbase",
    "copyright": "RWS",
    "location": "60b0a03152a974047fd46fb0",
    "termbaseStructure": {
        "languages": [ { "languageCode": "en-US" } ],
        "fields": [
            {
                "name": "Entry level field",
                "description": "A simple entry level field description.",
                "level": "entry",
                "allowCustomValues": true,
                "allowMultiple": true,
                "isMandatory": false,
                "dataType": "picklist",
                "pickListValues": ["picklist-value-1", "picklist-value-2"]
            }
        ]
    }
}
```

Response: `id`, `name`, `location` (`id`, `name`).

## Update a termbase

`PUT` [UpdateTermbase](../reference/UpdateTermbase.md) `/termbases/{termbaseId}` with `name`, `description`, `copyright` and `termbaseTemplateId` or `termbaseStructure`.

- Fields can be updated only if the termbase was not created from a template, or does not already have fields defined.
- `termbaseStructure` takes precedence over `termbaseTemplateId` if both are sent.
- A field sent without an `id` is added to the termbase.

## Read and delete

- [GetTermbase](../reference/GetTermbase.md) `GET /termbases/{termbaseId}`
- [ListTermbase](../reference/ListTermbase.md) `GET /termbases`: `numberOfEntries`, `status`, `createdAt`, `lastModifiedAt` are not available in the list.
- [DeleteTermbase](../reference/DeleteTermbase.md) `DELETE /termbases/{termbaseId}`

## Termbase templates

Endpoints: [CreateTermbaseTemplate](../reference/CreateTermbaseTemplate.md) `POST /termbase-templates`, [UpdateTermbaseTemplate](../reference/UpdateTermbaseTemplate.md) `PUT /termbase-templates/{termbaseTemplateId}`, [GetTermbaseTemplate](../reference/GetTermbaseTemplate.md), [ListTermbaseTemplates](../reference/ListTermbaseTemplates.md), [DeleteTermbaseTemplate](../reference/DeleteTermbaseTemplate.md).

| Rule | Detail |
|---|---|
| `location` | If omitted, the template is created in the root folder |
| `type` in responses | `system` (e.g. Basic, Advanced) or `userDefined` |
| Delete | Only `userDefined` templates can be deleted |
| Picklist | If `dataType` is `picklist`, `pickListValues` must be filled in or `allowCustomValues` must be `true` |

Template body: `name`, `description`, `location`, `copyright`, `languages[]` (`languageCode`), `fields[]`.

Field properties: `name`, `description`, `level` (`entry`, `language`, `term`), `dataType` (examples in docs: `text`, `boolean`, `picklist`, `double`), `allowMultiple`, `isMandatory`, `pickListValues`, `allowCustomValues`. Read with `fields=name,location,description,languages,fields` (see [fields.md](./fields.md)).

## Entries

| Operation | Endpoint |
|---|---|
| Create | [CreateTermbaseEntry](../reference/CreateTermbaseEntry.md) `POST /termbases/{termbaseId}/entries` |
| Update | [UpdateTermbaseEntry](../reference/UpdateTermbaseEntry.md) `PUT /termbases/{termbaseId}/entries/{entryId}` |
| Get | [GetTermbaseEntry](../reference/GetTermbaseEntry.md) `GET .../entries/{entryId}` |
| List | [ListTermbaseEntries](../reference/ListTermbaseEntries.md) `GET .../entries` |
| Delete one | [DeleteTermbaseEntry](../reference/DeleteTermbaseEntry.md) |
| Delete all | [DeleteTermbaseEntries](../reference/DeleteTermbaseEntries.md) `DELETE /termbases/{termbaseId}/entries` |

Entry body: `humanReadableId` (optional, any value; autogenerated without a guaranteed format if omitted), `languages[]` (`language.languageCode`, `terms[]` with `text` and optional `termbaseFieldValues[]`).

```json
{
    "humanReadableId": "LC000000000000000000000001",
    "languages": [
        { "language": { "languageCode": "en" }, "terms": [ { "text": "Simple Entry" } ] }
    ]
}
```

Read with `fields=humanReadableId,languages.terms,languages.terms.termbaseFieldValues`.

### Update behaviour

Update replaces the entire entry structure; terms not specified in the request are deleted. Re-send current structure (with `id` values) for anything that must stay unchanged. See [put-semantics.md](./put-semantics.md).

### Cross-references

Reference types: `entry`, `term`, `external` (value is an external URL). For `entry`, the identifier is the target's `humanReadableId` (UI: **Copy Entry ID**). Create through `fieldValueLinks` in a `termbaseFieldValues[]` item; `termbaseFieldId` must match the termbase field `id`.

```json
{
    "termbaseFieldId": "61b71de9877e04258abc7d9f",
    "value": "This is an new&nbsp;<a data-value=\"LC61b7264d877e04258abc7da8\" data-type=\"concept\" href=\"#conceptId=LC61b7264d877e04258abc7da8\">entry reference</a>",
    "fieldValueLinks": [ { "type": "entry", "value": "This is a new entry reference" } ]
}
```

The identifier `LC61b7264d877e04258abc7da8` appears twice in the HTML snippet (`data-value` and `href`).

## Import

Supported formats: `tbx`, `xml`. Create the termbase first.

`POST` [ImportTermbase](../reference/ImportTermbase.md) with `termbaseId` and the file. Optional query parameters:

| Parameter | Values | Default |
|---|---|---|
| `duplicateEntriesStrategy` | `ignore` (keep current entry with the same identifier, ignore new), `merge` (merge current content into imported entry; merged by text if no identifier), `override` (replace current with imported) | `override` |
| `strictImport` | `true` (import only if file language matches exactly a termbase language), `false` (import even with non-matching languages, matching them to a relevant main language or variant if available) | `true` |

Response: `importId` and `status`. Poll with [PollTermbaseImport](../reference/PollTermbaseImport.md) (`importId`, `termbaseId`); complete when status is `done`.

## Export

`POST` [ExportTermbase](../reference/ExportTermbase.md) with `termbaseId`. Optional body: format (`tbx` or `xml`; default `tbx`) and compression flag (zipped; default `false`). Response: `exportId`, `status`, `downloadUrl`; on failure `errorMessage`.

Poll with [PollExportTermbase](../reference/PollExportTermbase.md) (`exportId`, `termbaseId`); complete when `done`. Download with [DownloadExportedTermbase](../reference/DownloadExportedTermbase.md) (`exportId`, `termbaseId`).

See [async-polling.md](./async-polling.md).
